# 작품 컨셉 기반 생성 사양

## 목표

장르나 분위기 라벨을 추가하는 대신, 작품을 움직이는 **서사 전제(story concept)**를 구조화해 저장한다. AI 부트스트랩과 이후 회차 생성이 같은 전제의 목표·대립·위험을 유지하도록 한다.

## 조사에 따른 용어 구분

- **컨셉**: 주인공이 어떤 촉발 사건을 겪고, 무엇을 원하며, 무엇과 맞서고, 실패하면 무엇을 잃는지에 대한 차별화된 서사 엔진.
- **장르**: 판타지·무협·로맨스·미스터리 등 독자 기대와 관습의 범주.
- **테마**: 작품이 탐구하는 가치·질문·주제의식.
- **배경/세계관**: 사건이 일어나는 시간·공간·사회 규칙.
- **톤/문체**: 진지함·코믹함·기괴함 등 표현 방식. 컨셉 자체의 enum으로 취급하지 않는다.

근거와 상세 분석은 [`docs/research/2026-09-17-novel-concept-taxonomy.md`](../../research/2026-09-17-novel-concept-taxonomy.md)에 기록한다.

## 데이터 계약

`projects.concept`는 nullable JSON 객체다. API에서 허용하는 구성요소는 다음과 같다.

| 필드 | 의미 | 상한 |
| --- | --- | ---: |
| `summary` | 주인공·촉발 사건·목표·대립·위험을 연결한 한 문장 전제 | 1000자 |
| `protagonist` | 결핍·능력·출발점 | 500자 |
| `inciting_incident` | 이야기를 시작시키는 촉발 사건 | 500자 |
| `goal` | 주인공의 구체적인 목표 | 500자 |
| `opposition` | 목표를 막는 인물·세력·조건 | 500자 |
| `stakes` | 실패 시 잃는 것 또는 치를 대가 | 500자 |
| `hook` | 이 작품만의 차별화된 서사 장치 | 500자 |

컨셉 객체는 최소 한 필드가 비어 있지 않아야 하며, 정의되지 않은 키는 거부한다. 컨셉 생략은 허용한다. 생략을 `정통`·`코믹` 같은 임의의 작품 방향으로 변환하지 않는다.

## 적용 범위

1. AI 부트스트랩 요청·응답과 프로젝트 생성·수정·조회
2. 부트스트랩의 발상·목차·캐릭터·권별 조연·관계/로어 프롬프트
3. 일반 회차 생성·계획·병렬 생성·감수의 공유 컨텍스트
4. AI가 컨셉을 생성한 경우 구조화된 결과를 프로젝트에 저장
5. AI 실패/미사용 폴백에서도 사용자가 입력한 컨셉을 보존

## 프롬프트 계약

컨셉은 장르·테마·배경·톤과 분리된 `[작품 컨셉 — 서사 전제]` 블록으로 변환한다.

- 구성요소는 장면의 목표·장애물·선택·결과·관계 변화로 구현한다.
- 사용자가 제공하지 않은 구성요소는 기존 정본과 장르 문법을 우선해 보완한다.
- 핵심 목표·대립·위험을 임의로 바꾸거나 컨셉 문구만 반복하지 않는다.
- AI 발상 단계는 사용자가 컨셉을 주지 않은 경우 동일한 구성요소를 제안한다.
- 컨셉 입력은 사용자 데이터이지만 기존 정본·보안·시스템 규칙을 덮어쓰는 명령으로 승격하지 않는다.

## 저장·호환성

- Alembic migration `j5a6b7c8d9e0`이 nullable JSON 컬럼을 추가한다.
- 기존 프로젝트에는 의미가 다른 컨셉을 임의 backfill하지 않고 `null`로 둔다.
- migration 적용 및 실행 중인 개발/운영 DB 변경은 별도 승인 경계다.
- 과거 API에서 컨셉을 생략한 프로젝트 생성은 계속 동작한다.
- 기존 프로젝트의 과거 회차·원고는 컨셉 추가만으로 재작성하지 않는다.

## UI

- AI 부트스트랩과 수동 프로젝트 생성에 한 문장 전제를 먼저 보여주고, 나머지 구성요소는 펼쳐 입력할 수 있게 한다.
- 홈 프로젝트 카드에는 전제 요약을 표시하고 구성요소 편집 대화상자를 제공한다.
- 각 입력은 `label`/`id`를 연결하고 키보드로 접근 가능해야 한다.
- 컨셉과 톤·분위기·장르를 선택 목록 하나로 섞지 않는다.

## 검증 기준

- 구조화 컨셉의 API·DB 왕복과 부분 구성요소 보존
- unknown key·길이 초과·완전 빈 객체의 422 검증
- 컨셉 생략 시 `null` 보존
- 부트스트랩 모든 단계와 shared generation context의 행동 규칙 블록 전달
- AI/폴백 부트스트랩의 선택 컨셉 보존 및 AI 제안 컨셉 저장
- migration upgrade/downgrade 시 기존 프로젝트와 참조 데이터 보존
- 접근 가능한 UI 입력·편집 및 TypeScript/Vite 빌드
- 실제 provider/운영 DB 없이 격리 테스트 수행

## 범위 밖

- 컨셉을 장르·톤 enum으로 대체하는 것
- 한국 웹소설 시장의 장르별 판매·독자 데이터 최적화
- GPT/Gemini provider 계약 변경
- 기존 원고의 자동 재작성
- 컨셉만으로 반복 목차 문제를 해결하는 것
