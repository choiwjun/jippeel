# D01 회차 목표 영속화 — 조사 완료·요구 결정 대기

이 문서는 조사와 소유자 질문이며 **상세 사양·구현 승인이 아니다**. M01~M05/B03은 수용 완료로 유지한다. [원장 D01](../../handoffs/2026-09-08-remaining-work.md), [조사 원문](../../audits/d01-goal-contract-2026-09-13/research.md.txt), [원본 manifest](../../audits/d01-goal-contract-2026-09-13/manifest.json)를 따른다.

## 소스로 확인한 현재 상태

- `EpisodeBrief`는 생성 요청의 선택적 구조체다. DB 저장 모델이 아니다(`backend/app/schemas.py:408–424`). 브리프가 있으면 필드/목적별 검증을 적용한다.
- `aiPanelStore.ts:393–395`의 `episodeBrief`는 단일 메모리 값이다. 별도 회차 directive map도 영속 브리프 저장이 아니다.
- `Chapter.memo`는 빠른 메모, `Chapter.revision`/`ChapterSnapshot`은 원고의 경쟁 저장·복원 계약이다. 목표 내용/목표 버전과 혼용하지 않는다(`backend/app/models.py:52–106`).
- 생성은 첫 await 전에 현재 브리프와 purpose를 복제한다. 불완전한 브리프는 경고 후 요청에서 제외하는 기존 경로이며, 목표 저장을 추가한다는 이유로 이 동작을 조용히 바꾸지 않는다(`frontend/src/components/panels/AiPanel.tsx:265–355`).
- 조사는 읽기 전용이다. 소스·schema·migration·운영 자원은 변경하거나 실행하지 않았다. 부모가 B03의 현재 16개 소스/보호 hash 불변을 확인했다.

## 먼저 정할 제품 요구 — 과거 목표를 남길 것인가

| 선택 | 제공 범위 | 의미·비용 |
| --- | --- | --- |
| A. 최신 목표만 저장 | 작품/회차별 최신 내용과 충돌 방지용 목표 버전·기준 원고 버전 | 가볍지만 덮어쓴 과거 목표의 내용은 조회·복구할 수 없다. 버전 번호만으로 과거 내용을 재구성할 수 없음 |
| B. 목표 변경 이력도 보존 | 과거 목표 내용의 조회·복원까지 요구에 포함 | 별도 이력/복원 계약과 UI가 필요하지만, D03의 목표↔원문 근거 연결과 변경 추적에 유리 |

**부모 권장: B.** 장기 집필 흐름에서 기준 목표가 바뀌었을 때 과거 판단 근거를 잃지 않는 편이 낫다. 다만 D01의 필수 요구로 아직 승인되지 않았으므로 자동 채택하지 않는다. 조사자가 제시한 최신값 1행 최소안은 **과거 내용 조회/복원이 이번 필수 범위가 아니라는 확인**이 전제다.

## 후속 대화·인계 — 2026-09-13

사용자가 “어떤게 문제야?”, “해결방안이야?”라고 확인했다. 새 실행 오류가 아니라 **현재 목표 영속 기능의 부재**이며, 핵심 해결책은 **DB 저장·재시작 복원**, 이력은 **이전 목표 조회·복원이라는 추가 기능**이라고 설명했다. 추천은 두 기능의 조합이지만 A/B 선택은 아직 없다. 이후 **“핸드오프에 모두 남기고 커밋 푸시해”**는 인계·Git 게시 승인으로만 반영한다. D01 상세 사양·개발은 미착수다.

## 상세 사양 단계에서 명시할 사항

아래는 검토 후보이며 아직 소유자 승인으로 간주하지 않는다.

- 원고/빠른 메모와 분리한 회차별 목표 저장, 별도 낙관적 버전. 회차 간 늦은 로딩·저장 응답이 현재 입력을 덮지 않는 계약.
- 저장 버튼과 미완성 초안 저장 여부. 요청용 유효 `EpisodeBrief`와 작성 중 양식의 표현을 분리할 필요.
- 원고 복원과 목표 복원의 관계, 빈 값/삭제와 버전 경쟁, 목표의 기준 원고 버전이 무엇을 뜻하는지.
- purpose는 현재 별도 directive이므로 목표와 함께 복원할 항목인지 명시. 기존 serial/volume_end/series_finale 검증·점수 의미는 유지.
- AI 생성에 현재 입력값 또는 저장값 중 무엇을 사용하는지 명시하되, 기존 요청 동결·원고 flush·provider 시작 취소·실패 처리 계약을 보존.
- 선택한 이력 범위에 맞춰 합성 DB/fake-provider 회귀·이관 소스 설계. 실제 migration/운영/credential/provider 실행은 별도 승인 경계.

사용자 선택 후 좁은 D01 상세 사양과 검증 계획을 작성·검토하고 승인 후 개발한다. D03/D04는 필요한 인터페이스만 예고하며 이 단계에서 구현하거나 D02를 추가하지 않는다.
