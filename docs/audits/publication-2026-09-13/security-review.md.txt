## Targeted source findings

**Blocking: none.**

**[A1] LOW — `backend/app/routers/ai_panel.py:280` — inherited provider-error reflection.**
Attack scenario: a local bridge returning sensitive details in an otherwise unclassified API error can have that message relayed to the local UI/SSE consumer. The staged diff demonstrates the fallback already existed; this change substitutes the provider label and does not newly expose OAuth tokens. No live leaking response was observed. Suggested follow-up: return a stable generic message for unclassified provider errors and retain only explicitly sanitized diagnostics; add a fake-error test containing a synthetic sentinel. This is not a publication blocker or a request for unrelated deployment redesign.

Other checked controls: the fixed provider does not load OAuth credentials; loopback configuration errors are fixed text; writing/canon/bootstrap use `make_client(provider.base_url, None)`; legacy endpoint compatibility remains separate. Canon consumes JSON with shape checks rather than evaluation. Memory writes use SQLAlchemy expressions, project ownership checks and conditional update predicates. Isolation handles Windows case/stream/trailing-name aliases at `backend/tests/isolation_guard.py:149`; supported tracked entrypoint installs isolation before pytest. The changed dev requirements declare coverage tools only; no vulnerability-feed query, installed-package audit, or broader dependency certification was performed.
