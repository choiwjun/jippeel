# 스토리 지도 안정화와 근거 읽기 검증

게시 지시(2026-10-05): 사용자 “커밋 푸시해”에 따라 본 변경과 증거를 `origin/main`에 선별 게시한다. 아래 stage/commit/push 미실행 문구는 검토 당시 기록이다. 정확한 게시 결과는 Git 이력을 따르며 후속 기능의 QA·migration 미완료 판정은 유지한다.

## 최신 후속 구현 — 예정 회수와 검토안 처리 이력

사용자 후속 “계속 진행해”에 따라 예정 복선 회수와 검토안 비교·채택/보류/폐기 기록을 구현했다. **이 추가분은 코드 구현·정적 확인·독립 검토까지이며 동작 수용 완료가 아니다. 아래 1001P/14P/26P 결과는 이전 구현의 기록이다.**

- 예정 회수는 실제 회수와 다른 nullable 참조다. 복선 관리에서 저장/해제하고 지도에서 작가 계획으로 표시한다. 현재 revision이 일치해야 저장하며 계획 참조 회차는 삭제 409로 보호한다.
- 검토 결정은 작성한 검토안/이유와 당시 원문·근거를 이력에 추가한다. 원고·기억·목표를 자동 변경/승인하지 않으며 stale 경고를 해제하지 않는다. 근거 지문·마지막 결정이 달라지면 409다.
- 독립 검토 `/root/story_map_review`: 삭제 후 ID 재사용, 탐색 중 초안 소실, 빈 작품의 이력 접근, 일정 재조회 경합, 늦은 ACK의 새 초안 삭제를 지적했다. `review_key` 생성 식별자·복선 AUTOINCREMENT·초안 임시 보관·지도 루트 이력·입력 잠금·제출 초안 동일성 확인으로 보완했다. 최종 읽기 재검토 통과. reviewer는 파일 수정/테스트를 실행하지 않았다.
- 정적 확인: Python 변경 8개 파일 AST 파싱 통과. 최종 TypeScript와 임시 Vite 빌드는 [후속 빌드 로그](review-plans-build.log)를 따른다. 운영 dist는 교체하지 않았다.
- 자동 테스트 추가·실행, 브라우저 QA, migration 실행은 하지 않았다. 앞선 통과 수치를 이번 코드에 적용하지 않는다. [통합안의 후속 QA 잔여](../../specs/2026-10-05-story-map-evolution.md#후속-구현-결과와-수용-잔여)를 확인해야 한다.
- 새 migration `k6b7c8d9e0f1`은 복선 테이블을 재구성하고 검토 이력 테이블을 만든다. 실제 DB·서버 재기동·Git 게시 전 단계다. stage/commit/push는 수행하지 않았다.
- 한계: 검토안 결정 후 실제 반영은 기존 편집 화면에서 별도 수행한다. 초안은 같은 탭에서만 임시 보관한다. 전체 작품 기반 지문은 무관한 변경에도 재확인을 요구할 수 있고 전체 후보 조회 비용은 남아 있다.
- 후속 소스 지문은 [별도 manifest](review-plans-manifest.json)로 보존한다. 아래 원래 manifest와 로그를 덮어쓰지 않았다.

## 이전 단위 수용 기록


날짜: 2026-10-05. 범위: [통합안](../../specs/2026-10-05-story-map-evolution.md)의 1단계 안정화와 2단계 첫 읽기 기능. 운영 적용·전체 고도화 완료를 뜻하지 않는다.

## 수정·구현 범위

- 1단계: 권/전체 보기의 현재 회차 페이지, 저장 후 중복 조회, 늦은 최초 조회, 미리보기의 저장 상태, 삭제된 탐색 기준 회차의 오류 복구.
- 관계: 현재 작가 설정과 시점·승인·원문 근거가 있는 변화 기록을 구분한다. 인물 이름/ID 양쪽 기존 계약을 지원하며 타 작품·잘못된 ID를 제외한다. 폐기/수정 후속 행이 있는 과거 승인 기록을 되살리지 않는다.
- 복선: 설치·실제 회수 타임라인과 미래 회차 표시. 해결·의도적 미해결·외전 이관을 구분하고, 뒤의 두 종류는 처분 기록 회차로 표시한다.
- 변경 검토: 오래된 기억·목표와 근거 버전, 기존 내용 발췌, 승인/미승인 상태를 표시한다. 원고나 승인을 자동 변경하지 않는다.

## 재현과 독립 검토

수정 전 API 페이지 테스트 2건 실패, 브라우저 페이지/중복/미리보기/늦은 응답 4건 실패로 결함을 재현했다. 독립 검토가 삭제된 anchor 복구와 coordinator 직접 구독·최초 요청 취소를 확인했다.

2단계 독립 검토에서 ID 기반 관계 누락, 기억 승인 구분 누락, 복선 처분 구분 누락을 지적받아 보완했다. ID 사건 수정 후 관계가 사라지는 사례와 동일 회차 120사건의 해시 120회 실행을 API 테스트로 재현했다. 수정 후 같은 회차는 원문을 한 번만 읽고 해시를 한 번 계산한다.

독립 검토자 `/root/story_map_review`는 읽기 전용으로 1단계와 2단계 수정본을 각각 재검토했고 최종 추가 차단 결함 없음으로 판정했다. 이 판정은 코드 검토이며 테스트 실행 판정과 구분한다.

## 실패 실행과 한계

- 최초 지도 브라우저의 첫 페이지가 60초 안에 로딩되지 않은 실행이 있었다. fixture 캐시를 운영 Vite와 분리하고 초기 로딩 허용 시간을 기존 스위트 수준으로 조정한 뒤 전체 14건이 통과했다. 기능 assertion의 허용 시간은 10초를 유지했다.
- 원고 보존 최초 실행 역시 페이지 로딩에서 지연돼 serial 그룹이 실행되지 않았다. 병행 실행을 중단하고 단독으로 재실행했다. [중단 로그](manuscript-preservation-interrupted.log)를 최종 성공 로그와 구분한다.
- 공식 backend runner는 `-k` 옵션을 import 전에 거부했다. 허용된 테스트 파일 인자로 재실행했다.
- 전체 후보를 조회한 후 근거 응답을 페이지로 나눈다. 임의 규모의 장편 지연 시간을 보장하는 수용이 아니며 대형 실사용 자료 성능 확인은 잔여다.
- 예정 복선 회수 일정 저장, 검토 제안 비교·처리 이력, 실제 AI 참고 정보 설명, 생성 재개·긴장도·품질 비교는 미구현이다.
- 운영 재기동·migration·배포·stage·commit·push는 수행하지 않았다.
