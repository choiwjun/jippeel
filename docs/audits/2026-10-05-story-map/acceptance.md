## 최신 통합 UX — 인물과 이야기의 연결

- 기본 화면을 `StoryWorkbench`로 전환했다. 이전 회차 → 이번 목표 → 다음 계획, 인물 선택/임의 복수 조합, 관계망·승인 사건·복선 연동, 장면 순서와 인물 언급 조합을 표시한다. 인물 성격·배경·말투, 원고 언급 근거, 관련 세계관, 승인 요약·목표 전문은 접어둔 상세에 둔다. 기존 네 그래프는 별도 탭에서 탐색한다.
- `GET /projects/{pid}/story-map/workbench`는 작품 소유권을 확인하는 읽기 전용 API다. 승인+동일 원문 사건, 폐기/대체 제외, 동일 revision/hash 승인 요약만 서사 근거로 사용한다. 인물-복선은 같은 승인 사건에 함께 기록된 연결이다. 직접 관계를 새로 추론하지 않는다.
- 현재 인물 설정과 회차별 승인 기록을 구분한다. 원고/장면의 이름·별칭은 언급 후보이며 실제 등장·동행을 확정하지 않는다. 공유 이름은 배정하지 않고 긴 이름을 우선 매칭한다. 장면 초안은 원고 반영 여부를 뜻하지 않는다. 여러 인물 선택은 한 명 이상과 연결된 자료(OR)임을 표시한다.
- 독립 읽기 검토에서 하위 조회 갱신 누락과 ‘전체’ 표시의 일부 내용 누락을 지적했다. 지도 전체 하위 조회 취소/재조회, workbench revision 키/불일치 시 숨김, 승인요약·사건 전문과 모든 목표 필드로 보완했다. 최종 읽기 재검토 통과. reviewer는 파일 수정·테스트·DB 접근을 하지 않았다.
- `frontend/story-demo.html` + `src/demo/storyWorkbenchDemo.tsx`는 실제 컴포넌트에 합성 캐시를 제공하는 독립 체험 페이지다. 자동 query/retry/focus refetch를 끄고 인물 편집 링크는 안내로 처리한다. Vite 다중 진입으로 개발/빌드 모두 포함한다. 지도 ‘예시로 먼저 보기’로 열 수 있으며 실제 원고·승인·DB를 만들지 않는다.
- 정적 확인: TypeScript noEmit, 변경 Python 3개 AST 파싱, [임시 Vite 빌드](workbench-build.log) 통과. 운영 dist는 교체하지 않았다. [화면 캡처](workbench-preview.png)는 API/외부 요청을 차단한 합성 페이지 렌더다. 자동 테스트 추가/실행·브라우저 상호작용 회귀 검증은 하지 않았으며 이전 단위 통과 수치를 적용하지 않는다.
- 현재 backend에는 지도 API가 없고 기존 migration 적용/재시작 승인은 여전히 대기 중이다. 새 보드·체험 페이지는 미커밋이다. 대형 작품 전체 후보 조회 비용, 이름이 일반 단어와 겹치는 언급 후보의 정밀도, 정식 상호작용/접근성/저장 회귀 QA는 남아 있다.

## 최신 후속 구현 — 예정 회수와 검토안 처리 이력

사용자 후속 “계속 진행해”에 따라 예정 복선 회수와 검토안 비교·채택/보류/폐기 기록을 구현했다. **이 추가분은 코드 구현·정적 확인·독립 검토까지이며 동작 수용 완료가 아니다. 아래 1001P/14P/26P 결과는 이전 구현의 기록이다.**

- 예정 회수는 실제 회수와 다른 nullable 참조다. 복선 관리에서 저장/해제하고 지도에서 작가 계획으로 표시한다. 현재 revision이 일치해야 저장하며 계획 참조 회차는 삭제 409로 보호한다.

- 독립 검토 `/root/story_map_review`: 삭제 후 ID 재사용, 탐색 중 초안 소실, 빈 작품의 이력 접근, 일정 재조회 경합, 늦은 ACK의 새 초안 삭제를 지적했다. `review_key` 생성 식별자·복선 AUTOINCREMENT·초안 임시 보관·지도 루트 이력·입력 잠금·제출 초안 동일성 확인으로 보완했다. 최종 읽기 재검토 통과. reviewer는 파일 수정/테스트를 실행하지 않았다.

- 최초 지도 브라우저의 첫 페이지가 60초 안에 로딩되지 않은 실행이 있었다. fixture 캐시를 운영 Vite와 분리하고 초기 로딩 허용 시간을 기존 스위트 수준으로 조정한 뒤 전체 14건이 통과했다. 기능 assertion의 허용 시간은 10초를 유지했다.
- 원고 보존 최초 실행 역시 페이지 로딩에서 지연돼 serial 그룹이 실행되지 않았다. 병행 실행을 중단하고 단독으로 재실행했다. [중단 로그](manuscript-preservation-interrupted.log)를 최종 성공 로그와 구분한다.
- 공식 backend runner는 `-k` 옵션을 import 전에 거부했다. 허용된 테스트 파일 인자로 재실행했다.
- 전체 후보를 조회한 후 근거 응답을 페이지로 나눈다. 임의 규모의 장편 지연 시간을 보장하는 수용이 아니며 대형 실사용 자료 성능 확인은 잔여다.
- 예정 복선 회수 일정 저장, 검토 제안 비교·처리 이력, 실제 AI 참고 정보 설명, 생성 재개·긴장도·품질 비교는 미구현이다.
- 운영 재기동·migration·배포·stage·commit·push는 수행하지 않았다.

### 디자인 후속 — 대비와 리듬

사용자의 ‘각 요소가 밋밋하고 강약이 없다’는 피드백으로 기능 배치를 유지하고 시각 위계를 바꿨다. 짙은 청회색 현재 회차 헤더와 큰 회차 번호, 현재 목표의 상단 강조선, 인물별 고유색 카드·관계 노드, 관계 라벨 배경, 사건 번호와 금빛 강조, 복선 상태 배지, 장면별 번호·강조색, 차분한 상세 패널을 적용했다. 밝은/어두운 테마별 색과 선택/hover/focus/reduced-motion도 반영했다.

- 예시 독립 검토에서 가운데 클릭으로 실제 작품에 진입하는 href와 고정 미래 표시를 지적했다. 예시 관리 링크를 실제 URL 없는 안내 버튼으로 교체하고 Source.future를 조회 회차별로 계산했다. 보완 후 최종 읽기 검토 통과.
- WSL의 기존 Vite가 파일 변경을 감지하지 않아 이전 디자인을 내보내는 현상을 응답 소스로 확인했다. 프런트만 PID 154052로 재시작하고 프로세스 단위 polling을 켰다. 기존 backend·DB는 변경하지 않았다.
- 현재 [밝은 화면](workbench-preview.png)과 [어두운 화면](workbench-dark-preview.png)은 실제 최신 컴포넌트의 합성 데이터 캡처다. 좁은 화면도 렌더해 보았다. API/외부 요청은 차단했다. 이는 상호작용 QA나 접근성 규격 통과 판정이 아니다.
- 최종 TypeScript noEmit·임시 Vite 빌드 통과. [소스 지문](workbench-manifest.json)은 이번 통합 보드와 디자인 변경을 별도로 기록한다. 운영 backend 반영·자동 테스트·Git 추가 게시 미완료 상태는 유지한다.
