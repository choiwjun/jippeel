## 1. 프로젝트 개요 및 목표

### 1.1 핵심 문제 정의

한국 웹소설 작가는 하루 수천~1만 자를 생산해야 하는 연재 리듬 속에서 다음을 반복적으로 겪는다:

| # | 문제 | 근거 |
| --- | ------ | ------ |
| P1 | **설정 관리 부담** — 장기 연재 시 캐릭터 말투·외형, 세계관 용어·마법체계 등의 설정이 흩어져 모순이 발생 | 오픈소스 소설 도구들(novelWriter·Manuskript 등)이 모두 이 영역을 해결 대상으로 삼음 (부록01) |
| P2 | **AI 도구 파편화** — AI 보조(LM Studio/KoboldCpp/GPT/Claude 등), 캐릭터 카드(SillyTavern), 원고 편집(novelWriter)이 각각 별도 앱이라 창작 흐름이 끊김 | 핸드오프 "하나의 대시보드로 통합" 목표 |
| P3 | **AI 글의 기계적 어색함** — AI 초안은 번역투·리듬 균일성 등 AI 티가 있어 그대로 게시하면 독자 이탈 → 별점 테러·연재 중단 리스크 | 부록02 (신과함께 돌아온 기사왕님 사례), 부록04 |
| P4 | **플랫폼 규정 리스크** — 문피아는 일반 연재 본문까지 AI 전면 금지, 노벨피아는 공모전 금지 + 순수 창작 원칙. AI를 쓰면 안 되는 게 아니라 **검수·윤문 없이 쓰면** 위험 | 부록03 |
| P5 | **연재 조건 체크 누락** — 노벨피아 PLUS 신청은 회차당 공백 제외 3,000자 이상 등 정량 조건이 있으나, 작가는 매번 수동 계산 | 부록03 §3 |

### 1.2 목표

노벨피아+문피아 **병행 연재 전략**을 채택한 한국 웹소설 작가 하나가,
**기획(캐릭터·세계관) → 집필(회차 에디터) → AI 보조(모델 무관 패널) → 윤문(AI 티 제거) → 연재 준비(분량·상태 확인)**의 전 과정을 **하나의 로컬 대시보드**에서 처리할 수 있게 한다.

### 1.3 성공 관점

- 창작 데이터 주권: 원고와 설정은 사용자 PC에만 존재 (로컬 우선).
- AI 의존 최소화: 어떤 LLM이든 연결 가능하게 설계하여 특정 벤더 종속 방지.
- 규정 준수 지향: AI는 "인간이 검수하는 보조"로 한정, 윤문은 품질 향상 목적(탐지 회피 목적 아님).

## 2. 사용자(이해관계자) 정의

### 2.1 주 사용자: 한국 웹소설 작가 페르소나

| 항목 | 내용 |
| ------ | ------ |
| 가칭 | **김도현 (32세, 남성향 판타지 신인 작가)** |
| 전략 | 남성향 판타지·무협(회귀·빙의 코드)으로 노벨피아 자유연재 + 문피아 무료연재 **병행** (추천_병행연재_최적장르.md 확정안) |
| 연재 리듬 | 일일 연재 지향, 회차 3,000~5,000자 (부록02 검증된 관행) |
| 능력 수준 | 코딩 비전공자. CLI 사용 미숙 → **앱 실행 후에는 GUI만으로 모든 기능 사용 가능해야 함** |
| AI 사용 습관 | LM Studio(로컬)와 클라우드(GPT·Claude)를 상황별로 혼용 — **모델 무관** 연결 필수 |
| 최우선 불안 | "AI 썼다고 들키면 별점 테러" / "문피아 규정 위반" → 검수 절차가 명시적인 윤문 흐름 선호 |
| 데이터 태도 | 원고 유실 절대 불허. 백업 가능한 단일 파일/폴더 구조 선호 |
| 기기 환경 | 개인 Windows PC 1대, 인터넷 있음, 클라우드 동기화 불요 |

### 2.2 이해관계자 및 관심사

| 이해관계자 | 관심사 | 요구사항 반영 |

## 3. 기능 요구사항

> 추적 번호: 각 요구사항의 **R-xxx**가 규약 v1의 공통 추적 ID이며, 괄호 안 FR/NFR은 문서 내 기존 참조용 ID이다. `traceability.json` links는 R-xxx 기준으로 관리된다.
> 수용기준: 각 표의 **수용기준** 열이 개별 요구사항의 완료 판정이며, §7은 모듈 단위 통합 판정이다.
> 우선순위: **Must**(MVP 없으면 안 됨) / **Should**(MVP에 포함되면 큰 가치) / **Could**(여유 시 포함) / **Won't**(MVP 범위 밖 — 백로그)

### M1. 원고/회차 에디터

| ID(R-xxx) | 요구사항 | 우선순위 | 수용기준 |
| ------------ | ---------- | :---: | -------------- |
| R-001 (FR-101) | 작품(프로젝트) 단위로 원고를 생성·열기·삭제할 수 있다 | Must | 프로젝트 생성→열기→삭제 각 동작 후 목록 즉시 갱신, 삭제 시 확인 대화상자 표시 |
| R-002 (FR-102) | 프로젝트 안에서 회차를 생성·정렬·삭제할 수 있으며, 권(volume) 단위 묶음 관리를 지원한다 | Should | 회차 생성·순서 변경·삭제 후 재시작해도 순서 유지, 권 생성 및 권 간 회차 이동 동작 |
| R-003 (FR-103) | 마크다운 기반 텍스트 편집기를 제공한다 (미리보기 포함) | Must | 제목/강조/목록 마크다운 샘플 문서 작성 시 미리보기 렌더링 결과가 문법과 일치 |
| R-004 (FR-104) | 글자 수를 실시간 표시하며, **공백 제외 카운트**를 별도 제공한다 (노벨피아 PLUS 3,000자 조건 확인용) | Must | 타이핑 중 1초 이내 글자 수 갱신, 공백 제외 카운트가 검증 샘플 1건 이상과 일치(A2 가정 검증 포함) |
| R-005 (FR-105) | 회차별 상태(초고/수정중/완료)를 지정·변경할 수 있다 | Must | 상태 3종(초고/수정중/완료) 지정·변경 후 재시작해도 유지 |
| R-006 (FR-106) | 편집 내용이 **편집 입력 정지 후 5초 이내** 자동 저장된다 (기본값 — 기획 단계에서 조정 가능; 저장 버튼 누락으로 인한 유실 방지) | Must | 편집 입력 정지 후 5초 이내 자동 저장(기본값 — 기획 단계에서 조정 가능), 저장 실패 시 사용자 안내 표시 |
| R-007 (FR-107) | 회차당 수만 자 원고에서도 타이핑 입력의 화면 반영이 **100ms 미만**으로 유지된다 (NFR-101과 동일 기준) | Must | 3~5만 자 원고에서 타이핑 입력의 화면 반영이 100ms 미만 유지(NFR-101과 동일 기준) |
| R-008 (FR-108) | 회차 메모(빠른 메모)를 별도 필드로 남길 수 있다 | Could | 회차 메모 저장·재표시·수정 동작, 본문과 별도 필드로 분리됨 |
| R-009 (FR-109) | 원고 전체/회차 단위 내보내기(파일로 저장)를 지원한다 | Should | .txt/.md 두 형식으로 전체/회차 단위 내보내기 파일 생성, 파일 내용이 원문과 일치 |
| FR-W1 | (Won't) 실시간 공동 편집, 버전 브랜치 관리, 클라우드 동기화 | Won't |
