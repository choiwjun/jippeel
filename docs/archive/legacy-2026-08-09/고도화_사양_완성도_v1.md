# 웹소설 완성도 고도화 사양 v1 (1~4단계)

> **작성일**: 2026-09-06
> **근거**: 대시보드_MVP_사양.md v0.4, HANDOFF.md (집필 프롬프트 고도화 이후), 부록06 §2 로드맵
> **목표**: MVP의 "이 화 단위 보조"에서 **"장편 연재 전체의 서사 일관성 + 회차 품질 루프"**로 확장
> **범위**: P1(맥락 주입·이름 일관성) → P2(장면 구조화) → P3(복선·canon) → P4(품질 진단)

## P1 — 맥락 주입 고도화 (저비용·즉시 효과)

| ID | 기능 | 내용 | 구현 위치 |
|----|------|------|-----------|
| G-001 | 목차 자동 주입 | AI 생성 시 현재 회차 `memo`(부트스트랩 시놉시스·핵심 사건)와 **다음 회차 목표**를 컨텍스트 블록으로 자동 포함. `context.auto_outline` 플래그, start SSE 이벤트에 `injected_outline` 공개 | `routers/ai_panel.py::_build_context_blocks` |
| G-002 | 부트스트랩 이름 일관성 | 콜 1(idea)에서 `protagonist_name`을 먼저 확정 → 콜 2(목차)·콜 3(캐릭터)에 강제 전달. 콜 3 강제 규칙: "주인공 1명은 반드시 이 이름" | `services/bootstrap.py` |
| G-003 | 회차 간 연결 컨텍스트 확장 | 직전 회차 끝부분 주입 유지 + `[이번 회차 목표]` 블록은 프리셋 무관 항상 유효 | `routers/ai_panel.py` |

수용 기준:
- memo가 있는 회차에서 `auto_outline=true` 요청 시 메시지에 시놉시스 블록이 포함된다 (pytest 검증)
- 부트스트랩 응답의 캐릭터 목록에 콜 1에서 확정된 주인공 이름이 존재해야 한다 (실호출 스모크)
- 기존 테스트 회귀 0건

## P2 — 장면(Scene) 단위 구조화

| ID | 기능 | 내용 |
|----|------|------|
| G-010 | Scene 엔티티 | `scenes`: id, chapter_id FK, sort_order, title, content_md, created/updated. 회차 → 장면 계층 |
| G-011 | Scene CRUD API | `GET/POST /chapters/{cid}/scenes`, `PATCH/DELETE /scenes/{sid}`, `PATCH /chapters/{cid}/scenes/order` (bulk, 회차 reorder와 동일 원자성 규칙) |
| G-012 | 장면 단위 AI 생성 | `GenerateContext.scene_id` — 현재 장면 본문을 `[현재 장면]` 블록으로 주입(회차 전체 대신). 이어쓰기는 장면 경계 기준 |
| G-013 | 장면으로 회차 본문 조립 | `PUT /chapters/{cid}/content_from_scenes` — 장면들을 sort_order 순으로 합쳐 content_md 갱신(선택 기능, 자동 아님) |

수용 기준: Scene CRUD 테스트 + reorder 원자성(422) 테스트 + scene_id 주입 테스트.

## P3 — 복선 관리 + canon 충돌 게이트

| ID | 기능 | 내용 |
|----|------|------|
| G-020 | 복선(foreshadows) 테이블 | id, project_id, title, content, keywords[], status(설치|회수|보류), planted_chapter_id(FK nullable), resolved_chapter_id(FK nullable) |
| G-021 | 복선 CRUD | `GET/POST /projects/{pid}/foreshadows`, `PATCH/DELETE /foreshadows/{fid}` |
| G-022 | 미회수 복선 자동 주입 | `GenerateContext.auto_foreshadow` — status=설치(미회수) 복선 상위 N개(설치 최신순, limit 5)를 `[복선 경고]` 블록으로 주입. AI가 이 화에서 회수해야 할/건드려도 되는 복선을 알고 전개함 |
| G-023 | canon 충돌 검사 | `POST /api/v1/canon-check` — {chapter_id}. 회차 본문 + 캐릭터 카드 + 로어 + 미회수 복선을 컨텍스트로 LLM 1콜(비스트리밍, JSON) → 모순 후보 목록 `[{quote, reason, severity}]`. LLM 실패 시 502. 결과는 응답으로만 반환(이력 저장은 백로그) |

수용 기준: 복선 CRUD 테스트 + 미회수만 주입되는지 테스트 + canon-check 프롬프트 조립 테스트(fake LLM).

## P4 — 회차 품질 진단 (로컬 규칙 기반, LLM 불필요)

| ID | 기능 | 내용 |
|----|------|------|
| G-030 | 품질 지표 엔진 | `services/quality.py` — 대사 비율, 평균 문단 길이(초단문 리듬), 어미 반복도(~했다/이었다·~하게 된다 빈도), 접속사 남발(그러나/한편), 문단 첫머리 다양성, **후크 진단**(마지막 300자에 질문·위기·반전 시그널 여부), 노벨피아 공백제외 글자 수 |
| G-031 | 진단 API | `GET /api/v1/chapters/{cid}/quality` — 지표 + 점수(0~100) + 개선 제안 문구(한국어) |
| G-032 | 프리셋 연동 | 진단 결과가 임계 초과 시 대응 프리셋(장 끝 후크·AI 티 제거)을 AI 패널에서 바로 실행할 수 있도록 `suggested_preset_names` 반환 |

수용 기준: 결정적 텍스트(고의로 나쁜 샘플)에서 지표가 임계를 벗어나는지 규칙 테스트. 외부 의존(im-not-ai) 없이 동작 — metrics_v2 재사용은 후속.

## UI 반영 (프론트)

1. AI 패널: "목차 자동 포함"(auto_outline), "미회수 복선 포함"(auto_foreshadow) 체크박스 + 주입 배지
2. 에디터: 장면 분할 패널(회차 내 장면 목록·추가·장면 선택 후 AI 실행) — 최소 동작 버전
3. 에디터 상태 영역: 품질 진단 버튼 + 지표 요약 + 제안 프리셋 바로가기
4. 복선 관리: 프로젝트 사이드(S4 로어북과 유사한 리스트) — 복선 목록·상태 변경

## 원칙 유지

- AI 결과 자동 삽입 금지(P1·FR-406) — 모든 신규 기능도 컨텍스트 주입/제안만
- 원고·설정 데이터는 로컬 SQLite(Alembic 마이그레이션 2건: scenes, foreshadows)
- 탐지 회피 암시 문구 0건, "품질 다듬기" 용도 고지 유지
