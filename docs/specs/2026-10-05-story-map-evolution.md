# 스토리 지도 중심 집필 플랫폼 고도화 통합안

작성일: 2026-10-05. 상태: 사전 정리·1단계 안정화와 2단계 첫 근거 읽기 구현 완료. 격리 QA·독립 검토 결과는 [최종 수용 기록](../audits/2026-10-05-story-map/acceptance.md)을 따른다. 후속으로 예정 회수 일정·검토안 처리 이력까지 코드 구현했으며 해당 추가분의 동작 QA와 migration은 미완료다. AI 참고 정보 설명과 3단계는 미구현. 사용자 요청 “좀전의 고도화방향과 이기능도 종합병합해줘”에 따라 기존 개선 방향과 다이어그램·그래프 기능을 하나의 제품 흐름으로 묶었다. 아래 2026-10-05 실행 기록에서 구현 범위와 잔여를 구분한다.

목표는 작가가 수백 화의 이야기를 쓰면서 현재 상황과 앞으로의 전개를 보고, 원고 수정의 영향을 확인하며, 검토한 내용을 다음 집필에 반영할 수 있게 하는 것이다. 현재 로컬 작가 중심의 제품 방향과 기존 회차 목표·장면·기억·인지 상태·감수·완결 기능을 활용한다.

## 통합된 사용 흐름

**스토리 지도에서 현재 위치 확인 → 이번 회차의 목표와 참고 정보 확인 → 집필 → 변경 영향과 설정 검사 → 작가 확인 → 다음 전개 갱신**을 하나의 작업 흐름으로 제공한다.

예를 들어 3화를 집필하는 작가는 지도에서 1~2화의 기록과 4~5화의 계획을 함께 본다. 3화에서 인물의 행동을 바꾸면 연결된 기억·목표·복선에 검토 표시가 생긴다. 작가는 근거와 변경 전후를 확인하고 필요한 계획을 수정한다. 새 정보는 승인 상태와 시점 조건에 따라 다음 AI 집필에 참고된다. 이 예시는 제안하는 경험이며 현재 구현 완료를 의미하지 않는다.

## 고도화 방향과 스토리 지도의 연결

| 기존 고도화 방향 | 통합 기능 | 작가가 얻는 결과 |
| --- | --- | --- |
| 한 회차의 집필 화면 통합 | 에디터와 스토리 지도를 연결하고 선택 회차의 목표·장면·인물·복선을 표시 | 현재 위치와 할 일을 보면서 집필 |
| 수정 영향 안내 | 지도에 재검토 표시를 붙이고 변경 검토 대기열과 연결 | 앞부분 수정 후 다시 확인할 곳을 찾음 |
| AI 참고 정보 공개 | 선택 회차의 참고 자료와 포함·제외·축약 이유, 원문 근거 표시 | AI가 무엇을 알고 집필하는지 확인 |
| 설정 검사 정확도 개선 | 회차별 인물 상태·지식·관계와 근거를 함께 조회 | 회상·거짓말·오해를 고려한 검토 |
| 실패한 생성 이어하기 | 생성 단계와 저장된 결과, 실패·재개 상태를 작업 표시 영역에 제공 | 완료한 결과를 보존하며 필요한 단계 재실행 |
| 작가 기준 품질 개선 | 채택·수정·폐기 이유와 평가 사례를 기록하고 변경 전후 비교 | 실제 수정 부담과 설정 오류의 변화 확인 |
| 장편 탐색과 복구 강화 | 사건·인물·복선 검색에서 원문으로 이동하고 버전 비교·복원 연결 | 오래된 근거와 필요한 버전을 쉽게 찾음 |

## 화면 구성

기본 배치는 왼쪽에 권·회차 목록, 가운데에 원고 에디터, 오른쪽에 접거나 펼칠 수 있는 스토리 지도를 둔다. 전체 구조를 볼 때는 지도를 확대한다. 좁은 화면에서는 원고와 지도 보기를 전환하고 선택한 회차를 유지한다.

지도에는 다음 네 가지 보기를 둔다. 처음부터 모든 노드를 펼치지 않고 기본 범위는 현재 회차와 앞뒤 회차로 제한한다. 앞으로 3~5회 계획을 빠르게 확인하고, 필요하면 권·작품 전체로 범위를 넓힌다.

| 보기 | 표시할 정보 | 주요 동작 |
| --- | --- | --- |
| 스토리 흐름도 | 지난 회차, 현재 집필 위치, 예정된 회차·장면·전개 | 회차 클릭, 권 단위 접기, 목표와 원문 열기 |
| 인물 관계도 | 관련 인물의 협력·대립 관계, 시점별 상태와 확인된 변화 | 인물 선택, 근거 회차 이동, 기준 회차 전환 |
| 복선 타임라인 | 복선의 설치·실제 회수·보류·예정 회수 지점 | 원문과 계획 비교, 미해결 항목 필터 |
| 진행률과 긴장도 | 작성·확정한 회차 수, 회차별 긴장도와 계획 곡선 | 범위 변경, 측정 기준·출처 확인 |

노드를 선택하면 목표, 관련 장면·인물·복선, 근거 발췌, 참고 기억, 검토할 항목이 상세 영역에 열린다. 선택 회차와 현재 집필 회차가 다르면 둘을 명확히 표시한다. 원고 이동 시 기존 저장·충돌·복구 계약을 사용한다.

## 지도에서 구분할 상태

집필 상태와 정보의 성격을 각각 표시한다. 계획·집필·퇴고·확정은 작업의 진행 상태다. 작가의 계획, 본문에 기록된 내용, 작가가 확인한 설정, AI 제안은 정보의 성격이다. 회차가 확정됐다는 이유로 본문 속 거짓말이나 인물의 오해를 사실로 승격하지 않는다.

- 현재 집필 회차는 테두리와 “집필 중” 라벨로 표시한다.
- 원문에 근거한 내용에는 근거 회차와 저장 버전을 연결한다.
- 예정된 전개는 점선과 “계획” 라벨로 표시한다.
- AI가 추정한 사건·인과·관계는 “제안”으로 표시하고 작가 확인 후 반영한다.
- 변경 영향이 있는 항목은 “재검토 필요” 라벨과 원인을 표시한다.
- 색뿐 아니라 라벨·선 모양을 함께 사용하고, 같은 내용을 키보드로 탐색할 수 있는 목록 보기를 제공한다.

기본 연결선은 회차 순서를 뜻한다. 사건의 인과관계는 별도 연결 의미와 근거가 있을 때만 표시한다. 기본 축은 권이 없는 회차를 마지막에 두는 권→순서→id의 공통 서사 순서를 따른다. 회상 등 작품 속 시간은 별도 정보로 다루며 회차 순서와 혼합하지 않는다.

## 원고 변경과 지도 갱신

1. 글을 입력하는 동안 현재 회차와 저장 대기 상태를 표시한다.
2. 저장 성공 후 새 원고 버전을 기준으로 회차 상태·글자 수 등 파생 정보를 갱신한다. 저장 실패나 충돌이 있으면 지도에서 마지막 저장본을 기준으로 보고 있음을 알린다.
3. 출처가 연결된 요약·근거 링크 등의 변경 영향을 찾아 검토 대기열과 지도에 표시한다.
4. 새로운 사건 추출, 관계 변화 추정, 영향의 AI 분석은 별도 분석 결과로 보관한다. 작가가 검토한 후 지도와 설정에 반영한다.
5. 분석 중 원문이나 계획이 바뀌면 결과에 사용한 버전을 비교해 오래된 제안으로 표시한다. 늦게 도착한 결과가 최신 원고·계획을 덮지 않게 한다.

출처 연결로 확인한 영향과 AI가 추정한 영향을 구분한다. 앞부분을 수정했을 때 연결되지 않은 모든 후속 회차의 영향을 완전하게 알아낼 수 있다고 가정하지 않는다. 첫 단계는 실제 연결 근거가 있는 항목부터 제공한다.

검토 대기열에서는 원문 변경 부분, 기존 요약·설정, 새 제안을 나란히 보고 채택·수정·보류·폐기한다. 기존 승인 기억과 변경 이력은 보존하고, 갱신 초안을 별도로 검토한다.

## 참고 정보와 설정 검사

지도에서 선택한 회차마다 AI에 포함할 목표·인물·로어·기억과 각각의 근거를 볼 수 있게 한다. 미래 사건, 시점 인물이 모르는 사실, 승인되지 않은 정보, 오래된 원문에 근거한 기억은 제외 이유를 표시한다. 축약된 정보는 축약 여부와 사용 범위를 알린다.

시점 제한은 지도에서 미래 계획을 보는 작가의 시야와 별도로 적용한다. 작가가 미래 계획을 열어 보았다는 이유로 현재 회차 생성에 그 내용을 자동 주입하지 않는다.

설정 검사는 확실한 모순과 작가 확인이 필요한 표현을 구분한다. 사망·퇴장 인물의 이름이 나온 경우 회상·인용·꿈·거짓말 여부를 고려하고, 인물이 아는 사실과 독자가 아는 사실을 구분한다. 결과에는 원문 발췌와 설정 근거를 연결한다.

## 생성 재개와 품질 개선

기존 요약 작업의 영속 상태·재시도·원천 검증을 참고해 작품 생성·집필·감수의 단계별 결과 저장과 재개를 설계한다. 완료 단계의 결과를 보존하고, 재개 전에 입력 원문·계획 버전을 확인한다. 작품 속 사건 흐름과 AI 작업의 실행 상태는 각각의 표시 영역에서 확인한다.

기존 생성 이력·채택 기록·수정 정도 분석에 작가의 채택·폐기 이유를 연결한다. 회상·대화·전투·권말·최종화 등의 대표 사례에서 설정 모순, 인물 말투, 인과관계, 목표 이행, 반복 표현, 수정 시간을 비교한다. 만족도·수정량·수용률을 함께 해석하고 승인된 규칙만 이후 집필에 적용한다.

진행률은 표시한 범위의 회차를 분모로 삼고 작성과 확정을 별도 집계한다. 계획 변경 시 분모도 표시하며 회차가 없으면 빈 상태로 안내한다. 긴장도는 작가 입력 또는 AI 제안이라는 출처를 명시한다. 현재의 자유 텍스트 감정 곡선을 검증된 수치로 취급하지 않으며 값이 없는 구간은 미측정으로 남긴다.

## 기존 기반과 추가 설계 대상

| 영역 | 현재 활용할 기반 | 추가로 설계할 내용 |
| --- | --- | --- |
| 회차 흐름 | Chapter, ChapterGoal, Scene, 집필 단계·재개 정보 | 지도용 조회, 선택 동기화, 접기·검색·목록 보기 |
| 인물과 복선 | Character, Relationship, KnowledgeState, EventImpact, Foreshadow | 기준 회차별 관계 조회, 관계 변화의 근거, 계획한 회수 시점의 별도 저장 |
| 수정 영향 | MemoryEntry 출처·stale, 목표 근거 링크, 결말 영향 조회 | 영향 사유·검토 대기열, 갱신 초안 비교와 처리 이력 |
| AI 참고 정보 | 공통 ai_context와 포함 항목 metadata | 제외·축약 이유, 근거 표시, 분석 기준 버전 |
| 실행과 평가 | SummaryJob, GenerationRun, generation_analysis, 평가 manifest | 다른 생성 경로의 단계 저장·재개, 대표 사례의 비교 절차 |
| 탐색과 복구 | 원고 snapshot, 회차 목표 이력, 백업·복원 기반 | 지도에서 근거·버전으로 이동하는 UI |

현재 Relationship의 텍스트 관계를 과거 모든 회차의 관계라고 단정하지 않는다. 시점별 근거가 부족하면 “시점 정보 없음”으로 표시하고 관계 변화의 이력 계약을 추가 설계한다. 예정된 복선 회수 시점도 실제 회수 기록과 분리한다. 상세 저장 구조와 API는 후속 사양에서 정한다.

## 개발 순서와 완료 조건

| 단계 | 범위 | 확인할 결과 |
| --- | --- | --- |
| 1단계 집필과 지도 연결 | 회차 목표 중심의 흐름도, 현재 위치, 앞으로 3~5회 계획, 회차 상세 연결, 작성·확정 집계 | 지도에서 회차와 목표를 찾고 원고로 이동할 수 있음. 계획·현재·확정이 구분되고 저장 실패·충돌 중에도 작업본 보존 |
| 2단계 근거와 변경 검토 | 인물 관계·복선 보기, 시점 정보, 수정 영향과 검토 대기열, AI 참고 정보 설명 | 계획과 실제 기록을 구분함. 연결된 변경 영향의 원인을 추적하고 갱신 제안을 검토할 수 있음. 미래 정보·오래된 결과가 현재 집필에 혼입되지 않음 |
| 3단계 재개와 품질 고도화 | 생성 단계 저장·재개, 문맥을 고려한 설정 검사, 긴장도 곡선, 품질 비교, 장편 검색·복구 동선 | 완료 결과를 재사용해 재개하고, 오탐·설정 오류·수정 부담의 변화를 같은 사례에서 비교할 수 있음 |

각 단계는 요구사항 구체화→필요한 디자인→개발→격리 QA 순서로 진행한다. 기존 기능을 중복 구현하지 않도록 먼저 현재 API와 상태 계약을 대조한다. 1단계는 이미 저장된 회차·목표·상태를 중심으로 구현할 수 있는 범위부터 상세화한다.

## 2단계 첫 구현 범위 — 관계·복선·변경 근거 읽기

현재 데이터 조사: Relationship에는 시점·원고 버전이 없고, EventImpact에는 승인 상태·근거 회차·원문 해시가 있다. Foreshadow에는 설치·실제 회수 회차만 있고 예정 회수 회차는 없다. MemoryFreshness는 실제 원문 버전/해시와 하위 출처의 승인·신선도를 재귀 판정한다. 이 기반을 재사용해 읽기 영역부터 연결한다.

- 지도에서 선택한 회차 상세에 `목표 / 관계 / 복선 / 변경 검토` 보기를 둔다. 탭을 열었을 때만 근거를 조회한다.
- `GET /projects/{pid}/story-map/evidence?chapter_id=…&view=relations|foreshadows|review&offset=…`는 작품/회차 소속을 검사하고 한 페이지 50개를 반환한다. 지도 선택과 AI 생성 선택은 계속 분리한다.
- 관계: 작품의 현재 작가 설정은 **시점 정보 없음**으로 표시한다. 기준 회차까지의 승인 관계 변화는 원문 해시가 일치하는 기록만 별도 표시한다. 미래·초안·폐기·원문 변경 기록을 역사적 사실로 섞지 않는다. 관계 설정 자체를 과거 상태로 역산하지 않는다.
- 복선: 등록된 설치→실제 회수 기록을 회차 순서로 표시한다. 선택 회차보다 뒤의 기록은 **선택 회차 이후**라고 표시한다. 기록되지 않은 설치/회수 시점은 미등록이다. 현재 disposition/status가 기준 회차 당시 상태라고 단정하지 않는다. 예정 회수 시점 저장은 별도 사양·DB 변경이 필요한 잔여다.
- 변경 검토: 작품 전체에서 오래된 기억과 원고 버전이 달라진 목표를 모은다. 원문 변경/출처 누락/연결된 기억 불일치 등의 확인 가능한 이유와 기준·현재 버전, 기존 내용 발췌를 제공한다. 자동 수정·재승인하지 않으며 기존 기억 관리로 연결한다. 새 제안과 비교·채택·보류·폐기 처리 이력은 다음 단위다.
- 근거 회차 버튼은 해당 회차 주변으로 지도를 옮겨 **살펴보기**만 수행한다. 집필 이동은 기존 저장 확인 동작을 재사용한다.
- QA: 타 작품 ID 배제, 미래 사건·초안·stale 사건 배제, 시점 없는 관계 라벨, 복선 미래 표시, 원고 수정 후 stale 대기열·버전 표시, 페이지 상한, 근거 살펴보기 시 원고/AI 회차 유지.

이 단위는 2단계 전체 완료가 아니다. 예정 회수 일정·검토 처리 이력·실제 생성 기준 참고 정보 설명은 후속 구현으로 남는다. 새 DB 스키마나 provider 호출은 필요하지 않다.


### 2단계 검토 보완과 검증 범위

- 독립 코드 검토에서 인물 ID 관계 변화 누락, 승인/초안 라벨 누락, 복선 처분 라벨 누락을 지적받아 보완했다. 같은 작품의 ID만 이름으로 바꾸며 bool·음수·타 작품 ID를 제외한다.
- 사건 승인/폐기는 append-only 이력이므로 후속 기록이 있는 과거 승인 행을 관계 변화로 다시 표시하지 않는다. 원문 해시가 없거나 다른 사건도 지도 근거에서 제외한다.
- 의도적 미해결·외전 이관의 회차 참조는 ‘실제 회수’ 대신 ‘처분 기록 회차’로 표시한다. 미승인 기억 초안과 승인 기억을 따로 표시한다.
- 같은 회차의 사건 120개에서 원문 해시 호출이 120회이던 것을 회차별 1회로 줄였다. 변경 전 테스트는 ID 수정 후 관계 0개 및 해시 120회로 실패했고, 수정 후 통과했다.
- API focused 22건 통과(격리 위반 0). 읽기 전용 독립 검토 최종 통과. 전체 회귀·브라우저 결과는 최종 수용 기록에서 확정한다.
- 성능 한계: 지도는 메타데이터 전체를 읽고, 근거 목록은 전체 후보의 유효성을 판단한 후 응답을 50개씩 자른다. 500회 지도와 동일 회차 120사건의 조회/해시 계약을 확인했으며 임의 규모 장편의 성능을 보장하지 않는다.
- 실행 환경 기록: 공식 backend runner는 `-k` 인자를 거부해 테스트 import 전에 중단했다. 허용된 파일 경로 인자로 재실행했다. 브라우저 첫 시동/첫 페이지에서 WSL 소스 파일 처리 지연이 있었으며 fixture 전용 Vite 캐시와 직접 실행 명령으로 운영 dev 캐시와 분리했다. 기능 실패와 시동 timeout은 구분한다.

## 후속 구현 계약 — 예정 회수와 검토안 처리 이력

사용자 후속 지시 “계속 진행해”에 따른 다음 개발 단위다.

- 복선에 nullable `planned_resolution_chapter_id`와 정수 `revision`을 추가한다. 기존 행의 예정 회수는 미등록으로 유지한다. 실제 회수·처분 회차와 별개이며 같은 작품의 회차만 연결한다. 복선 관리의 회차 선택에서 저장/해제하고 지도 타임라인에 ‘예정 회수 · 작가 계획’으로 표시한다. 계획 연결 회차 삭제는 기존 참조 삭제 계약처럼 409다. 계획 저장 시 조회 revision을 요구하고 충돌은 409로 보존한다.
- 검토 대기 항목마다 현재 근거 지문을 제공한다. 원문/기억/목표의 전체 내용과 연결 근거 변경을 감지하며, 제출한 지문과 현재 지문이 다르면 409다. 검토안은 작가가 작성한다. AI 호출은 추가하지 않는다.
- 기존 내용과 검토안을 나란히 표시한다. ‘검토안 채택 / 보류 / 폐기’는 결정과 이유를 append-only 이력으로 저장한다. 채택 시 검토안이 필수이며 원고·기억·목표의 자동 수정이나 자동 승인은 하지 않는다. 화면에서 별도 반영이 필요함을 명시한다. 현재 stale 경고는 결정만으로 사라지지 않는다.
- 이력은 작품에 속하며 대상이 삭제되거나 최신 대기열에서 빠져도 조회 가능하다. 마지막 이력 ID와 근거 지문을 확인해 중복·동시 제출을 막는다. 예전 결정은 당시 근거로 표시하며 현재 근거가 바뀌면 재검토가 필요하다.
- 화면: 복선 관리 카드에 예정 회수 선택, 지도 복선에 계획/실제 분리. 변경 검토 카드에 기존 내용·검토안·이유·처리 버튼·최근 결정, 작품 전체 이력 접기/펼치기와 페이지 조회를 제공한다.
- migration 파일과 시작 시 스키마 확인을 함께 변경한다. 운영 DB에 적용하거나 서버를 재기동하지 않는다. 이번 후속에는 자동 테스트 추가·실행 요청이 없어 정적 검사와 코드 검토까지 진행하고 동작 QA를 미완료로 기록한다.


### 후속 구현 결과와 수용 잔여

- 코드: 복선 모델/스키마/API/UI와 지도, `StoryReviewDecision`/검토 API/`StoryReview.tsx`, migration `k6b7c8d9e0f1`, 앱 시작 스키마 확인을 연결했다. 계획 참조 회차는 삭제 409로 보호한다.
- 독립 검토 보완: 목표·기억 삭제 후 SQLite ID 재사용은 생성 시각 기반 `review_key`로 구분하고 기존 조회 id는 유지했다. 복선은 모델·migration 모두 AUTOINCREMENT로 재사용을 막는다.
- 검토 초안은 작품+review_key 단위 메모리/sessionStorage에 기준 근거와 함께 저장한다. 같은 탭의 재진입/새로고침을 지원하고 저장소 오류를 알린다. 저장 성공 시 제출한 동일 초안만 제거해 늦은 ACK가 새 입력을 삭제하지 않는다. 탭 종료 후 미제출 초안 보존은 보장하지 않는다.
- 검토 이력은 지도 루트에서 선택 회차 없이 조회한다. 일정 재조회 중에는 입력을 잠가 응답이 새 선택을 덮지 않는다. 최종 독립 코드 검토 통과, 자동 테스트·migration·브라우저 QA는 미실행이다.
- 격리 QA 잔여: 계획의 생성/변경/해제·타 작품 거절·동시 수정 409·참조 삭제, migration 전후 기존 자료와 ID 비재사용, 검토 POST 원자성/근거 변경/중복 응답/이력 페이지/대상 삭제, 초안 이동/재진입/저장소 실패/늦은 응답, 빈 작품 이력, 기존 원고 보존 회귀.
- 성능: 근거 지문은 전체 작품의 기억/회차 상태에 보수적으로 의존한다. 무관한 근거 변경도 재확인을 요구할 수 있으며 장편 비용 최적화는 잔여다.

## 시각화 보완 — 사용자 “다이어그램 등의 그래프로 한눈에” 정정

기존 세로 회차 카드와 근거 목록은 시각화 요구를 충분히 충족하지 못했다. 목록 중심 화면을 보완해 한눈에 보기에서 다음을 함께 표시한다.

- 회차 흐름도: 현재 조회 범위의 회차를 연결된 노드로 배치한다. 현재 집필·선택 회차, 단계, 핵심 계획, 목표 재검토 표시를 보여준다. 화살표는 회차 순서이고 본문 인과관계 추론이 아니다.
- 인물 관계망: 여러 인물을 한 그래프에 연결하고 인물 선택으로 연결을 강조한다. 현재 설정과 승인 변화 기록을 분리한다. 동일 이름의 다른 인물은 ID로 구분하고 ID 없는 과거 기록은 이름 기반 기록으로 별도 표시한다.
- 복선 타임라인: 같은 회차 축에 여러 복선을 행으로 배치한다. 설치/예정 회수/실제 회수·처분을 다른 도형과 선으로 표시하고 기준 회차를 세로선으로 보여준다. 미등록 시점이나 계획을 실제 사실로 채우지 않는다.
- 회차별 집필 그래프: 저장 글자 수를 막대로 보여주고 현재 집필 회차를 표시한다. 긴장도 수치가 없으므로 이를 감정·긴장도 그래프로 대체하지 않는다.
- 노드/근거 클릭은 살펴보기만 바꾼다. 집필 이동은 기존 저장 확인 버튼을 사용한다. 전체 확대와 나란히 집필, 키보드 조작과 기존 목록 보기를 유지한다. 회차/근거 페이지와 차트 표시 상한을 명시한다.
- 실제 DB migration·backend 재시작 승인은 아직 대기 중이다. 그래픽 보완 자체에는 새 DB 스키마가 필요 없다. 자동 테스트 요청이 없어 타입/빌드·독립 코드 검토만 진행하고 동작 QA는 미실행으로 기록한다.


### 시각화 보완 결과

`StoryVisualOverview`에 4개 시각화를 구현하고 기존 목록/상세/저장 확인 이동을 연결했다. 관계 조회는 ID를 제공하고 ID 없는 기록은 동일인으로 추론 병합하지 않는다. 독립 검토 지적 보완 후 통과. 타입/임시 빌드/구문 확인까지 진행했으며 자동 동작 QA는 미실행이다. [예시 데이터 정적 미리보기](../audits/2026-10-05-story-map/visual-preview.png)는 실제 작품이나 API 검증 화면이 아니다. 현재 개발 backend에는 새 API가 없으므로 실제 작품 연결에는 승인 대기 중인 DB migration과 재시작이 필요하다.

## 통합 집필 보드 — 인물 조합과 이야기 흐름 중심 UX

사용자 정정: 캐릭터·현재 얽힌 조합·글의 흐름을 함께 보여주되 최대한 쉽게 읽혀야 한다. 첫 화면을 현재 회차의 상황과 인물 중심 보드로 바꾸고 기존 4개 그래프는 전체 지도 보기에 유지한다.

- 상단: 이전 회차 → 현재 회차(승인 요약/목표) → 다음 계획. 승인 요약이 없으면 미등록으로 표시하며 목표를 실제 사건으로 바꾸지 않는다.
- 중앙: 검색 가능한 전체 인물 목록, 선택 인물/조합과 직접 연결된 관계, 관련 장면·승인 사건·복선. 인물 또는 장면 조합을 선택하면 여러 영역을 함께 강조한다. 관계 설정에는 시점 없음, 승인 변화에는 근거 회차를 표시한다.
- 하단: 순서대로 놓인 장면 카드와 같은 장면의 이름 언급 조합, 현재 근거가 일치하는 승인 사건, 관련 설정. 세부 근거/전체 차트는 접어서 정보량을 조절한다.
- 조회 전용 `/projects/{pid}/story-map/workbench?chapter_id=…`를 추가한다. 실제 저장 원고·장면의 이름/별칭 문자열 일치는 ‘언급 후보’이며 실제 등장·동행을 확정하지 않는다. 여러 인물이 공유하는 이름/별칭은 자동 매칭에서 제외한다. 등록 인물 ID에 의한 승인 사건의 연결은 별도로 표시한다.
- 원문 해시가 다른 사건, 폐기/후속 이력으로 대체된 사건, 미래 사건은 현재 사건으로 쓰지 않는다. 장면 초안은 원고 반영이 보장되지 않음을 표시한다. 계획·현재 설정·승인 기록의 성격을 라벨로 유지한다.
- 현재 단위에 DB 변경/provider 호출은 없다. 실제 DB migration/서버 재시작 승인 대기 상태는 유지하며 예시 데이터는 별도 미리보기로 제공한다. 자동 테스트는 요청되지 않아 실행하지 않는다.

### 통합 집필 보드 구현 상태

- 인물 단독/복수 선택과 장면 조합 선택에 관계·승인 사건·복선을 연결했다. 그룹은 한 명 이상과 연결된 OR 범위이며 전체 복선 보기는 별도 선택이다.
- 인물 설정 상세/세계관/근거/모든 목표 필드를 접힌 패널로 제공한다. 요약·사건은 전문을 반환하고 장면·세계관·원고 언급은 발췌임을 명시한다.
- 지도 새로고침이 하위 조회를 갱신한다. 원고 revision별 workbench 조회와 버전 불일치 시 표시 보류로 최신 글자 수에 옛 근거가 섞이지 않게 했다. 자동 저장 갱신 중 선택은 유지한다.
- 독립 합성 체험 `/story-demo.html`와 지도 진입 링크를 추가했다. 실 데이터 저장/분석 없이 실제 컴포넌트를 탐색한다.
- 독립 읽기 검토·정적 확인까지 완료. 자동 동작 QA, 기존 DB migration·backend 재시작, Git 추가 게시는 미완료다. 자세한 결과는 수용 기록의 ‘최신 통합 UX’를 따른다.

### 디자인 강약 보완

사용자 후속 피드백에 따라 기존 탐색 UX를 유지하면서 현재 회차를 가장 강한 대비로 강조한다. 다음 순서는 현재 목표 → 관계망/선택 인물 → 사건/복선 → 장면 흐름 → 접힌 근거다. 인물 색은 목록·관계도·장면 칩에서 일관되게 사용한다. 사건은 금빛, 복선 회수는 녹색 상태, 장면 순서는 큰 번호와 강조선으로 구별하되 텍스트/형태를 함께 써 색에만 의존하지 않는다. 라이트/다크, 좁은 화면, 키보드 포커스, 모션 감소 선호를 지원한다. 최신 시안은 수용 기록의 workbench-preview / workbench-dark-preview를 따른다.

### 범위 전환 오류 수정 — 작품 전체와 회차 상세 분리

사용자 ‘작품전체를 클릭해도 왜 해당회차만 나오는가’ 신고. 코드 경로에서 scope는 map 조회 범위만 바꾸고 StoryVisualOverview는 기본 workbench/focus 한 회차를 유지하는 원인을 확인했다.

- 현재 주변은 회차 중심 보드, 작품 전체/선택 권은 해당 범위 전체 개요로 분리한다. 범위 버튼 클릭 시 목록·선택 회차를 초기화한다.
- 기존 25회 메타데이터 API를 페이지별로 끝까지 읽고, 모든 회차를 권별 압축 지도와 집필량에 표시한다. 원문 전체·AI 호출은 없다. 상세 계획만 접힌 12회 단위 페이지다.
- 전체 화면에서 회차를 누르면 해당 회차 보드로 이동한다. 실제 집필/AI 기준은 바꾸지 않으며 기존 저장 확인 집필 버튼을 유지한다.
- 작품 전체 관계는 마지막 회차까지의 승인 변화와 현재 설정, 복선은 작품 전체 등록 자료다. 근거가 많으면 기존 50개 API/그림 내부 페이지로 탐색하고 범위를 명시한다. 선택 권의 관계는 해당 권 마지막 회차까지 기록이며 복선은 여전히 작품 전체임을 표시한다.
- 페이지 수집 중 총 회차 수·중복 ID·offset·순서가 달라지면 다시 불러오도록 한다. 재조회 취소 signal과 기존 map 하위 무효화를 공유한다.
- 독립 읽기 검토에서 그래프 축 축소와 집계 불일치를 보완했고 최종 검토 통과. 집계는 표시 노드로 다시 계산한다. 여러 페이지가 동일 시점 스냅샷이라는 보장은 없다. 자동 테스트/회귀 QA는 이번 요청에 포함되지 않으며 새 migration/백엔드 재시작은 필요하지 않다.
